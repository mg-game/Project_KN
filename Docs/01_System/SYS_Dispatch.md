## 0. 요약
- 지금: 8구역 · 10분~3시간 · 3명까지 · 동시 3개 · 시간 사다리(기본 / 길게 ×3 / 밤새 ×6) · 보상 = 단추 + 수선 재료 + 호감도 + "원정 N회" 기록. **원정 중에도 편성에서 안 빠짐** (코드 주석 M05).
- ⚠ **D-27 #5(파견 중 편성 불가)를 그대로 넣으면 초반이 막힘**: M1 로스터 5~7명인데 원정 3개 × 3명 = 9명까지 묶임 → **지킴이 5칸을 못 채움**. 가드레일 필요 (§3 #1).
- 구역 이름 · 장소가 옛 동화책(비 오는 광장 · 다락방 · 분실물 보관소 · 별빛 세탁소) 기준 → D-53 기억등 지역으로 맞춤 (§3 #3).

## 1. 현재 구현 (추출)

### 1.1 규칙
```
보내기 TrySend(zone, members[1..3], tier)
  IF 구역 잠김 (requiredStage) OR 그 구역 진행 중 OR 동시 3개 가득 OR 계보가 다른 원정 중 → 거절
  시간 = 구역 시간 × {1, 3, 6}[tier] (12시간 넘는 단계는 없음 · 길게 · 밤새는 튜토리얼 뒤)
받기
  단추 = 구역 단추 × {1, 2.8, 5.4}[tier] × (1 + 0.25 × (인원 − 1))
  재료 = 줄마다 확률 × (1 + 0.15 × (인원 − 1)), 배율만큼 반복 굴림 · 이벤트 배율
  참여 계보마다 호감도 +{2, 4, 6}[tier] · "원정 N회" +1 (단계 무관)
다시 보내기 · 모두 다시 보내기 (마지막 친구 · 단계 기억)
가속: 별조각 (accelerateExpeditionCost = 4, 단위 [코드 확인])
편성: 원정 중에도 지킴이 · 잔향이로 그대로 싸움 (M05)
시간 처리 (I-5 · H-1 수정 — `ExpeditionSystem.cs` · `Core/Game.cs`)
  원정 시각 = DailyClock 유효 시각 = max(기기 시각, 본 적 있는 가장 늦은 시각) → 시계를 되돌려도 뒤로 가지 않음
  IF 원정 시각 < 시작 시각 → 시작 시각에 멈춤 (시작 · 종료를 당기지 않음 — maxSeen 갱신 전 되돌림도 같음)
  IF 시계 되돌림 (DailyClock.IsTampered, 300초 초과) → 받기 · 모두 받기 막음 + 토스트 "기기 시간이 이전으로 바뀌었어요…"
  시계를 앞으로 돌리는 것은 감지 안 함 (되돌리면 위 잠금) — 서버 시각 검증은 D-31 P1
  DailyClock 없이 만든 원정(옛 연결 · 시스템 단위 테스트)은 기기 시각을 그대로 쓰고 되돌림 때 시작/종료를 당긴다
```

### 2.3 흔적 연동 (P1, D-49)
- 유실표의 흔적 3칸 = **그 장 스테이지 파밍**으로 다 채울 수 있음 + **그 장 지역 의뢰 완료 시 흔적 +1** (가속).

## 4. 예외 처리 / 엣지 케이스
| 케이스 | 처리 |
|---|---|
| 원정 중 계보가 편성 프리셋(D-52)에 있음 | 불러올 때 그 칸만 비움 (D-52 메모와 같음) |
| 출발 가드에 걸림 | 버튼 회색 + 몇 명을 빼야 하는지 안내 ("1명만 보내면 출발할 수 있어요") |
| 앱 종료 중 원정 완료 | 받을 때까지 진행 중으로 셈 (현재) · 편성 잠금은 **완료 시각에 풀림** (받기 전이라도 싸울 수 있게) |
| 첫 만남 · 구조 직후 계보 | 바로 보낼 수 있음 (가드만 확인) |
| 던전 입장 | 원정 중 계보는 던전 편성 불가 (같은 잠금) |

> 💡 **조합 제안 (검토용)** — 의뢰 × 원물 성격
> 구역마다 **"이 의뢰를 반기는 원물"**(예: 우산살 구역 = 우산 · 천 특성)을 두고, 그 특성 계보를 보내면 재료 확률 +10%. 시너지 특성(K-07)을 원정에서도 쓰게 되어 "누구를 보낼까"가 편성과 다른 기준으로 갈림 — 싸움엔 안 쓰는 친구도 의뢰엔 쓸모가 생김.
