## 1. 현재 구현 (추출 — `SYS_Growth` §1 요약)
```
수선점 레벨 L (1 ~ 1000), 재화 = 단추
  비용(L → L+1) = levelUpBaseCost × levelUpCostGrowth^(L−1)
  수선점 내구 최대 = 300 × 1.04^(L−1)          # 스테이지 · 던전 시작 때 적용
  초당 단추 = 1 × 1.06^(L−1) × 재료 보너스 × (1 + 0.1 × (최고 스테이지 − 1))
  10레벨마다 별조각 50 우편
시설 · 잔향 친화 · 빛의 반경 = 없음 (잔향 수급 · 소환 상한은 BattleConfig 고정값)
```

## 2. 기획 방향 (To-be) — DD 설계안

### 2.1 시설 ↔ 축 매핑 (컨셉)
- **수선 작업대** = 수선점의 일 자체. 고치는 힘 = 버티는 힘(등불 내구) + 버는 힘(초당 단추). → 지금 레벨 1축의 정체가 이것.
- **기억 베틀** = 잊힌 기억을 짜서 잔향으로 만드는 곳 → 잔향 수급(잔향 친화).
- **기억등** = 수선점의 빛. 빛이 닿는 만큼 잔향이가 머물 수 있다 → 빛의 반경 · 소환 상한.

### 2.2 수선 작업대 (= 지금 수선점 레벨)
```
레벨 · 비용 · 내구 · 초당 단추 · 10레벨 별조각 = 지금 식 그대로 (SYS_Growth §1 A~D)
세이브 이전: facility.workbench = data.level  (손실 0, 전투력 변화 0)
```

### 2.3 기억 베틀 (잔향 친화)
```
레벨 1 ~ 20 [가정]
잔향 기본 수급 % = +1.5 × (레벨 − 1)            # 최대 +28.5% [가정] — ResonanceRegenPercent 합산 (시너지 D-50 · 도감 §SYS_Codex #1과 같은 능력치)
레벨 10 · 20 → 수선등 밝히기 시작 레벨 +1 (L1 → L2 → L3)   # §18.2 투자 단계 앞당김
비용 = 단추 × 곡선 + 수선 재료 (천 · 리본 조각) — 수치는 BAL 문서에서
```

### 2.4 기억등 (빛의 반경)
```
레벨 0 ~ 8 [가정]
소환 상한 summon_cap = 12 + 레벨          # 12 → 20 (D-28 #8 테스트 범위 12 · 16 · 20을 성장으로 흡수)
결계 링 반경 = 연출만 (링 크기 · 빛 번짐). 8방위 슬롯 위치 · 사거리 판정은 바꾸지 않음
비용 = 단추 + 수선 재료 + 달빛 조각(던전 10층~) — 레벨당 큰 결심, 자주 안 오름
```
- 링 반경을 **판정에 쓰지 않는 이유**: 지킴이 사거리 · 성향 반경(`charge_radius` 등)이 링 반지름 1 기준이라, 반경이 바뀌면 전투 밸런스 전체가 흔들림.

## 6. 확장성 · 유지보수
- **유지보수**: 작업대 = 기존 `GrowthSystem` 재사용 (이름만 시설로 감쌈) → 새 코드 = 베틀 · 기억등 2개 + 세이브 필드 1개. `StatType`에 `SummonCap` 1개 추가.
- **확장성**: 시설은 `Facility_Def` 행 추가로 늘어남 (P2 주민 방 · 비행 준비실은 `axis = None`). 시즌 시설 · 이벤트 시설도 같은 틀.
- 효과가 기존 능력치(`ResonanceRegenPercent` · `ShopMaxHp`)와 같은 `StatBlock`에 합산 → 전투력 · 강해지기 자동 반영.

> 💡 **조합 제안 (검토용)** — 시설 × 유실자 주민
> 구조한 유실자가 **시설에 "머무는" 주민**이 됨 (HM-001 주민 생활). 기억 베틀에 몽실(잔향 계열)이 머물면 베틀 효과 +10% 식으로, 수집형 로스터가 시설 성장의 곱셈 요소가 됨. 주민 배치는 전투 편성과 별개라 "싸움엔 안 쓰는 친구"에게도 자리가 생김 (`SYS_Dispatch` 💡와 같은 결).
