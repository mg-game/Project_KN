> 결론 먼저: 세이브는 **로컬 JSON 한 파일**이고, 깨짐 · 복구 쪽은 잘 짜여 있다(임시 파일 교체 · 직전 백업 · 날마다 백업 3 · 손상 격리 · 세이브 코드로 기기 이동). 약한 곳은 **"고친 세이브"** 쪽이다 — 파일 · 세이브 코드에 서명이 없어(코드는 CRC32뿐) 누구나 고칠 수 있고, **백업 복구 · 코드 가져오기로 소환을 되돌릴 수 있다.**
> 싱글 · 오프라인 · 랭킹 없음(원칙 P6)이라 **결제 전까지는 "자기 게임을 자기가 망치는 것"** 이라 M1은 I-14(로드 검증) · I-5(원정 시계)면 충분. **결제를 붙이는 순간 경계가 바뀐다** — 유료 별조각 · 뽑기는 서버가 정본이어야 하고(D-51 #6), 그때 계정 서버 · 서버 시각 · 클라우드 세이브를 **한 번에** 붙이는 것이 이 문서의 제안.

## 1. 현재 구현 (추출)

### 1.1 저장 형식 · 위치
- `Application.persistentDataPath/player.json` — `PlayerData` 전체를 JSON 한 파일로. `CurrentVersion` = **4** (2 = L&L 캐릭터 · 전투 · 원정, 3 = 메타, 4 = 4차 메타 — `MetaSave.MigrateToV4`).
- **별조각 2풀** (I-14 · D-30 #3): `gemPaid`(결제로 받은 몫) · `gemFree`(그 밖) 칸. `currencies[Gem]`은 둘의 합으로 유지 (화면 · 비교 · 옛 코드 호환). **버전은 4 그대로** — 옛 세이브는 두 칸이 0으로 읽히고 로드 때 `ReconcileGemPools`가 합 전부를 무료로 옮긴다 (몇 번 돌려도 같은 결과). 버전 5는 I-10g 튜토리얼 단계 id (D-63 #1).
- 열거형 키 딕셔너리(`currencies` · `linkedAccounts` · `LineageSave.progress`)는 **멤버 이름**으로 저장 → 이름을 바꾸면 그 키가 사라짐. 모르는 키는 로드 때 건너뜀 (`TolerantEnumKeyDictionaryConverter`).

### 1.2 저장 · 복구 (`SaveStorage`)
```
저장: 임시 파일에 쓰기 → 본 파일과 교체 · 직전 세이브는 player.json.bak
      그날 첫 저장 = player.json.day-{날 키}.bak (새것 3개)
      바꾸기 전(가져오기 · 복구) = player.json.{이유}-{유닉스}.bak (이유마다 새것 3개)
로드: 본 파일 → 실패 시 .bak → 둘 다 실패 = 읽지 못한 파일을 .corrupt-{유닉스}로 격리 · null (새 게임)
      결과 = 아직 안 읽음 / 첫 실행 / 백업에서 불러옴 / 실패 (복구 안내용)
      → Sanitize: null 칸 채우기 · 값 검사 · 별조각 풀 맞추기 (I-14) · 깨진 계보 · 원정 줄 버리기 · 버전 마이그레이션
         값 검사: 재화 · 별조각 풀이 음수 · NaN · ∞ → 0 · 재료 개수 음수 → 삭제 (고칠 때마다 경고 "[Save] 무결성")
         풀 맞추기: 유료 = min(유료, 합) · 무료 = 합 − 유료 (다른 경로가 합만 바꿔도 풀이 따라감)
      → 재료 상한: InventorySystem이 만들어질 때 상한(ItemDatabase.countCap, 임시 999,999)보다 많으면 상한으로 + 경고
      지급 · 소비 검사(로드 밖)는 SYS_Economy §2.1 (CurrencySystem · InventorySystem)
설정 [계정 · 데이터]: 백업 목록('오늘' · '어제' · '그저께' · 'M월 d일' · '가져오기 전' · '마지막 저장 직전') → 복구
                      데이터 초기화 = 세이브 + 백업 모두 삭제 (격리 파일만 남김)
                      플레이 기록 보내기 (D-58 #1 · 출시 빌드에도): 최근 24시간 요약 PlayLog.Summary(24)
                        → [내보내기] 최근 500줄 Tail(500) 공유 시트 · 못 하면 복사 (개발 탭 치트는 개발 빌드 전용 그대로)
새 기능(Replace · SnapshotDaily · ListBackups · RestoreBackup)은 예외를 내지 않고 경고 한 줄 (킬 스위치)
```

### 1.3 저장 시점 (`GameBootstrap`)
| 때 | 동작 |
|---|---|
| 30초마다 (`autoSaveInterval` 30) | 자동 저장 (백그라운드) · 일시정지 중엔 타이머 멈춤 |
| 앱이 뒤로 감 (`OnApplicationPause(true)`) | 동기 저장 + `PlayerPrefs.Save` |
| 돌아옴 | 오프라인 보상 계산 (`lastSaveUnix` 기준) |
| 종료 (`OnApplicationQuit`) | 동기 저장 + 백그라운드 저장 마무리 |
| 소환 · 받기 직후 | **따로 저장 없음** — 다음 30초 또는 뒤로 갈 때 (D-31 #5 즉시 저장 = P2) |

### 1.4 기기 이동 — 세이브 코드 (`SaveCode`)
- 형식 `LL1.{CRC32 8자}.{base64(gzip(JSON))}` · 풀린 크기 4 MB까지 · 더 새 버전 코드는 거절.
- 가져오기: 붙여 넣기 → 미리보기('스테이지 3-4 · 수선점 Lv.87 · 친구 6명' / '저장 … · ID 1a2b3c4d') → [이 진행으로 바꾸기] → 지금 진행은 `import` 백업 → 다시 시작.
- ⚠ **CRC32는 깨짐 확인용이지 서명이 아님** — 풀어서 고치고 CRC를 다시 계산하면 통과.
- `BackupReminderSystem` — 코드 백업 알림.

### 1.5 계정 (`AccountSystem`)
- 첫 실행 = 게스트 계정 ID 발급. 외부 연동 **Google · Kakao** (`AuthProviderType`) — `AccountService`는 **서버 없이 로컬에서 늘 성공하는 임시 구현**. 서버 · BaaS 미정.

### 1.6 시계
```
시간 공급자: LocalTimeProvider = 기기 UTC 하나 (서버 시각 없음)
DailyClock (F-01): 하루 = 현지 05:00 시작 · 주 = 월요일 05:00
  maxSeenUnix(본 적 있는 가장 늦은 시각) 저장
  IF 지금 < maxSeen − 300초 → IsTampered = true
     → 받기 멈춤 + "기기 시간이 이전으로 바뀌었어요. 시간이 다시 맞으면 받을 수 있어요."
     (출석 · 미션 · 업적 · 무료 빠른 수선 · 바구니 · 작은 선물 · 이벤트 · 수첩 · 쿠폰 · 응원 · 복귀 등 14개 시스템 + 화면 3곳이 확인)
  날 키 = max(지금, maxSeen) 기준 → 되돌려도 날이 거꾸로 가지 않음 · 시간대를 서쪽으로 바꿔도 저장된 날에 머묾
  앞당기기: 오프라인에선 못 막음 → 바구니 상한(8h · 12 · 16) · 하루 1회 제한으로 피해를 묶음
⚠ 예외: ExpeditionSystem 남은 시간 = 기기 시계 직접 (:214) — 앞당겼다 되돌리기로 원정 완료 · '원정 N회' 진화 조건 파밍 (I-2 H-1 → I-5)
던전 · 상점 하루 = DailyClock 날 키 (안전)
```

## 2. 기획 방향 (To-be) — DD

### 2.1 원칙
1. **P6 싱글 · 오프라인 · 랭킹 없음** → 남과 겨루지 않으니 **자기 진행 치트는 "막는 비용 > 피해"** 인 동안 막지 않는다 (막다가 정상 유저를 잠그는 쪽이 더 나쁨 — 예: 시계 오차 300초 허용).
2. **돈이 걸리는 곳만 서버가 정본** — 유료 별조각 · 뽑기 결과 · 천장 · 결제 영수증 (D-51 #6 · D-30 #3). 로컬 세이브 복구 · 수정으로 이 값들이 되돌아가거나 늘지 않아야 함.
3. **정상 유저의 진행은 절대 잃지 않게** — 깨짐 · 기기 변경 · 앱 삭제 대비가 치트 방어보다 먼저.

### 2.3 출시 전 — "서버 묶음" (P1, 결제 P0와 한 번에)
결제를 붙이려면 어차피 서버가 필요하다 (영수증 검증 · 서버 뽑기 · 확률 기록). **그 서버 하나에 아래를 같이 올린다.**
```
[계정]   게스트 ID → 서버 계정 (Google · Kakao · iOS는 Apple 로그인, §2.4)
[시각]   접속 시 서버 시각 받아 offset 저장 → DailyClock · 원정 · 바구니가 서버 기준 (D-31 #2)
         오프라인이면 기기 시각 + 마지막 offset, 초과분은 보류(막지 않음 — D-31 #2 그대로)
[지갑]   유료 별조각 = 서버 정본 · 무료 별조각 = 로컬 (D-30 #3)
[뽑기]   서버에서 뽑고 기록 (D-51 #6) → 백업 복구 · 코드 가져오기가 뽑기 · 유료 지갑 · 천장을 되돌리지 못함
         (로컬 세이브의 해당 칸은 서버 값으로 덮어씀)
[세이브] 클라우드 세이브 = ISaveStorage 구현 하나 더 (인터페이스 이미 있음) · 계정에 묶음
         충돌: 더 진행된 쪽(최고 스테이지 → 마지막 저장 시각) 보여 주고 고르게
[서명]   로컬 파일 · 세이브 코드에 HMAC 서명 (키는 빌드 안 — "못 고치게"가 아니라 "쉽게 못 고치게")
         서명 틀림 → 읽기는 하되 무결성 경고 기록 (정상 유저 잠금 X)
```

## 4. 예외 처리 / 엣지 케이스
| 케이스 | 처리 |
|---|---|
| 저장 중 앱이 죽음 | 임시 파일 → 교체라 본 파일은 직전 상태 유지 (현재) |
| 본 파일 · `.bak` 둘 다 깨짐 | 격리 + 새 게임 + 안내 — 날마다 백업이 남아 있으면 설정에서 복구 가능 (현재) |
| 더 새 버전 세이브 (업데이트 롤백) | 세이브 코드는 거절 (현재). 본 파일은 [확인 필요 — 더 새 버전 파일을 옛 앱이 읽을 때 모르는 칸 건너뜀 → 저장 시 사라짐] → P1에서 "더 새 버전이면 읽기 전용 + 업데이트 안내" |
| 시계 오차 (5분 안) | 되돌림 아님 (300초 허용) |
| 해외여행 · 시간대 변경 | 날 키가 거꾸로 가지 않음 · 서쪽 이동 시 저장된 날 유지 (현재) |
| 미래로 잘못 맞췄다 바로잡은 정상 유저 | 되돌림 감지로 받기 멈춤 → **maxSeen까지 기다려야 풀림** (I-2 M-3) — I-5에서 해제 경로 같이 볼 것 (지시에 이미 포함) |
| 계보 · 열거형 이름 변경 (I-7 이름 통일) | **코드 이름 · 세이브 키는 그대로** (D-57 #3 · `KN_M1_DevBrief` §0.1) — 바꾸면 세이브에서 사라짐 |

## 6. 확장성 · 유지보수
- `ISaveStorage` 인터페이스가 이미 있어 클라우드 저장소는 **구현 하나 추가**로 끝남. 백업 · 복구 · 격리 규칙을 그대로 재사용.
- 마이그레이션은 `Sanitize`의 버전 분기 한 곳 — M1 = 버전 5(튜토리얼 단계 이름 저장, D-63 #1), P1 서버 묶음 = 다음 버전 하나로 모으면 이전이 한 번.
- 시계는 `ITimeProvider` 하나로 모여 있어 서버 시각은 **공급자 교체**로 붙음 (원정이 I-5로 `DailyClock` 경유가 되면 예외 없음).

> 💡 **조합 제안 (검토용)** — 세이브 코드 × 수선 장부
> 세이브 코드 내보내기를 "수선 장부 사본"으로 연출 (도감 · 최애 유실자 초상이 찍힌 카드 이미지 + 코드). 기기 이동 기능이 **공유하고 싶은 카드**가 되어, 백업률이 오르고 SNS 노출도 생김. 코드 자체는 지금 형식 그대로.
