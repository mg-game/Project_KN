> 소환 이름이 이미 **"잃어버린 친구 찾기"**(`tableId: friends`)다. 이 문서는 소환을 컨셉의 "유실자를 찾아가 구조한다"와 어떻게 맞출지, 그리고 **결제를 붙이기 전에 반드시 갖춰야 할 법 요건**을 정한다.

## 0. 요약
- 지금: 등급 먼저(일반 45 · 희귀 33 · 영웅 15 · 전설 6 · 신화 1) → 등급 안에서 균등 · 단일 100 / 10회 900 별조각 · 천장 60회 = 전설 · 중복 = 기억 조각.
- ⚠ **D-49 #3 "구조한 캐릭터만 소환 풀"을 다시 봐야 함**: 그러면 소환 = **이미 가진 캐릭터의 중복만** 나옴 → "새 친구를 만나는 설렘"이 사라져 수익 구조가 약해짐 (§3 #1).
- ⚠ **천장이 거의 의미 없음**: 전설 이상 7%라 60회 안에 못 뽑을 확률 **1.4%** (§3 #3).
- ⚠ **법 요건 미충족**: 지금은 **등급별 확률만** 보여 줌 → 캡슐형은 **획득 가능한 모든 결과의 확률**을 구매 화면에 보여야 함. 결제 붙이기 전 P0 (§2.5).

## 1. 현재 구현 (추출)

### 1.1 규칙
```
Pull(count)                                                     # GachaSystem
  비용: 1회 100 · 10회 900 별조각 (10회 할인)
  FOR 각 회:
    pity += 1 · 등급을 가중치로 뽑음 (계보가 없는 등급은 빼고 다시 나눔)                 # RollGrade:152-166
    IF pity ≥ 60 AND 뽑힌 등급 < 전설 → 전설로 올림 (천장 결과 표시)
    → 그 등급 계보 중 균등
    새 계보 → 획득 (따라잡기: 시작 레벨 = PRG-05 규칙) / 중복 → 그 계보 기억 조각 (등급별 5 · 10 · 20 · 40 · 80)
    천장 카운트: 전설 **이상**(신화 포함)이 나오면 0으로 (:164)
PullGuaranteed(lineage)   # 첫 만남 (FTUE 10단계) — 무료 · 천장 · 확률 · 마일스톤에 안 셈
마일스톤: 누적 10 · 30 · 50 · 100 · 200회 보상, 100회 = 친구 선택권 (전설 이하 1명 고르기), 그 뒤 반복
확률 표시: 등급별 % (계보 없는 등급 제외)
```

### 1.2 지금 로스터(M1 7명) 기준 캐릭터별 확률
| 등급 | 등급 확률 | 캐릭터 | 1회당 캐릭터별 |
|---|---|---|---|
| 일반 | 45 % | 똑단이 | 45.0 % |
| 희귀 | 33 % | 키키 · 몽실 | 각 16.5 % |
| 영웅 | 15 % | 짝짝이 · 루루팝 | 각 7.5 % |
| 전설 | 6 % | 레이니 | 6.0 % |
| 신화 | 1 % | 엘리제 | 1.0 % |
- 새 게임 별조각 = 시작 300 + 환영 1,000 (+ 계정 연동 300) → **첫날 13~16회**. 엘리제를 16회 안에 만날 확률 ≈ **15%**.
- 공명 0 → 10 = 기억 조각 1,100 (D-29). 똑단이(중복 5개)는 중복 220번, 레이니(40개)는 28번.

## 2. 기획 방향 (To-be) — DD

### 2.1 소환의 정체 — "유실물 종을 따라 바로 찾아가기"
컨셉: 유실자는 유실표 → 흔적 → 조우 → 구조로 만난다 (`SYS_Rescue`). 소환은 이 길의 **지름길**로 정의한다.
```
[소환] = 유실물 종이 울린 곳으로 바로 찾아가 데려오기 (연출: 종 → 문 → 실루엣 → 이름)
  IF 이미 함께인 친구 → 기억 조각 (그 친구의 흔적이 더 모임)
  ELSE IF 아직 구조하지 않은 친구 → "먼저 만남": 손님으로 바로 합류
       → 그 친구의 유실표는 장부에 "만남 완료"로 남고, 구조 이야기 · 구조 전투는 나중에 그 장에서 그대로 진행 (보상 = 기억 조각 + 이야기)
```
- 효과: **새 친구를 소환으로 먼저 만나는 설렘**은 살리고, **구조 이야기는 누구나 보게** 함 (이야기가 소환 결과에 따라 사라지지 않음).
- D-49 #3("구조한 캐릭터만")을 이 규칙으로 바꾸자는 제안 (§3 #1).

### 2.2 풀 · 확률 구조
| 항목 | M1 | 정식 (P1 BM) [가정] |
|---|---|---|
| 풀 | 등장한 7명 전부 (지금) | **출시된 캐릭터 전부** (§2.1) |
| 등급 확률 | 지금 그대로 (45 · 33 · 15 · 6 · 1) | BM 단계에서 재조정 — 아래 원칙 |
| 천장 | 60 → 전설 (지금) | **신화 천장 + 픽업** (§2.3) |

원칙 (정식):
1. 등급 = 성격 · 사용 난도(P3), **강함의 서열이 아님** → 낮은 등급도 끝까지 쓰임 (공명 · 개화로)
2. 신화 · 전설은 "만나고 싶은 최애"가 몰리는 곳 → 천장으로 **언젠가 반드시** 만나게
3. 캐릭터 수가 늘면 같은 등급 안 1인 확률이 줄어듦 → **픽업**(기간 한정 확률 상승)으로 원하는 친구에 집중

### 2.3 천장 · 픽업 [가정 — BM에서 수치 확정]
| 항목 | 규칙 |
|---|---|
| 신화 천장 | 누적 100회 안에 신화가 안 나오면 100번째 신화 확정 · 신화가 나오면 카운트 0 |
| 전설 천장 | 없앰 (전설 이상 7% → 60회 천장은 1.4% 경우에만 작동, 의미 없음) — 또는 BM에서 등급 확률을 낮출 때 다시 |
| 픽업 | 소환 탭에 "이번 달의 친구" 1명 — 그 등급이 나오면 50%로 픽업 친구 · 픽업 실패 다음 그 등급은 픽업 확정 (반천장) |
| 표시 | 천장까지 남은 횟수 · 픽업 확정 여부를 소환 화면에 항상 |

### 2.4 중복 · 사용처
- 중복 = 그 친구 기억 조각 (등급별 5 · 10 · 20 · 40 · 80, 현재). 사용처 = 공명 · 한계 돌파(D-45) · 진화 재료 대체 · 조건 가속.
- 공명 10까지 1,100 → 등급 낮은 친구일수록 중복이 많이 필요하지만 확률도 높음 → BM에서 "평균 몇 회에 공명 10" 시뮬레이션 (`BAL_ProgressionSim`, P1).

## 6. 확장성 · 유지보수
- 픽업 · 기간 한정 소환 = `GachaTable` 1행 추가 (코드 수정 없음)
- 확률표 화면 · 홈페이지 페이지는 **같은 데이터에서 자동 생성** → 표시 오류(법 위험) 원천 차단

> 💡 **조합 제안 (검토용)** — 소환 × 유실표 장부
> 소환 결과 화면에 **유실표 카드가 함께 넘어오는** 연출: "이 아이의 유실표에는 이렇게 적혀 있었어요 — '비가 그친 뒤에도…'". 소환이 단순 뽑기가 아니라 "찾아낸 이야기"로 읽히고, 구조 이야기(나중)의 예고편이 됨. 중복일 때는 유실표 대신 "흔적 +N" 카드.
