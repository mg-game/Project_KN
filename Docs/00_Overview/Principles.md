# mg-game 10계명

> 팀이 판단할 때 기준이 되는 원칙. 세부 규칙(CONTRIBUTING.md R1~R10)과 부딪히면 **계명이 방향, 규칙이 방법**이다.
> 같은 내용이 Notion 홈과 웹 팀 보드에도 걸려 있다. 원본은 이 파일.

| # | 계명 | 실행 기준 |
|:-:|---|---|
| 1 | **우리는 모두 기획자이자 개발자이자 아티스트다** | 직군은 없다. 필요한 일이 보이면 누구든 한다 |
| 2 | **빠르게 만들고, 빠르게 내놓는다** | 완벽보다 출시가 먼저다. "돌아가면 일단 올린다" |
| 3 | **초반이 재미없으면 후반은 없다** | 첫 플레이의 후킹에 집중한다. 후반 콘텐츠는 나중에 생각한다 |
| 4 | **내 방향대로 가되, 공통 룰 안에서 간다** | 남의 눈치를 보지 않는다. 단, 팀 룰(폴더·네이밍·브랜치)은 지킨다 |
| 5 | **남의 작업도 내 작업이다** | 마음에 안 들면 바꾼다. 대신 이유를 커밋이나 PR에 한 줄 남긴다 |
| 6 | **불만은 그 자리에서, 뒤끝은 없이** | 마음에 안 들면 바로 말한다. 말한 순간 끝, 담아두지 않는다 |
| 7 | **꼬이면 그때 모이고, 모르면 추천대로 간다** | 문제가 생기기 전에는 회의하지 않는다. 막히면 추천안으로 진행하거나 회의를 연다 |
| 8 | **아트는 한 사람이 그린 것처럼** | 통일된 풍과 컨셉을 지킨다. 기준은 아트 레퍼런스 보드 하나 |
| 9 | **QA와 기획은 늘 곁에 있다** | 만들면서 플레이하고, 플레이하면서 기획한다. 작업 단계를 따로 나누지 않는다 |
| 10 | **AI와 자동화로 시간을 사고, 돈은 아낀다** | *(제안 · 확정 필요)* 두 번 반복되는 일은 AI·자동화부터 검토한다. 유료 도구는 무료 대안이 없을 때만 쓴다 |

## 계명 → 실제 장치

| # | 어디서 지켜지나 |
|:-:|---|
| 1 | 팀 보드 "모자" · CONTRIBUTING §0 (D-1) |
| 2 | 검수는 "돌아가는가 + 룰 위반 없는가"만 본다 (R3). 검수 1일 대기면 보드가 "검수 대기"로 띄움 (R10) |
| 3 | 마일스톤 완료 조건에 "첫 5분 후킹" 플레이테스트 포함 (M1) |
| 4 | 폴더 구조 · 파일명 · 브랜치 규칙 (CONTRIBUTING §2·§6, Docs/README.md) |
| 5 | **완료된 작업**은 누구든 바로 고친다 + 이유 한 줄. **진행 중인 카드**는 주인에게 한마디 하거나 "넘겨받기" 후 고친다 (R1 · R8과 충돌 방지) |
| 6 | 팀 보드 메모 · PR 코멘트에 바로 남긴다 |
| 7 | 정기 회의 없음. 보드 "꼬임 · 막힘"이 뜰 때만 모인다. 판단이 안 서면 DD 추천안으로 진행 |
| 8 | Notion **아트 레퍼런스** 보드가 유일한 기준. 채택은 대표 결재함 |
| 9 | 작업판은 단계(기획→개발)로 나누지 않는다. 카드 하나에 기획·개발·아트 모자를 함께 단다 |
| 10 | 개발 지시함 · AI 팀원(DD · 기개발 · 로컬 · AI 아트) · CI |
