## 1. 적용 순서와 정본

1. [결정 기록](../decisions.md)에서 **해당 항목의 최신 결정**과 승인 상태를 확인한다. 이후 [용어집](../00_Overview/KN_Glossary.md), 캐릭터 원본, 외형변경 문서를 읽는다. `Review` 자료를 자동으로 `Approved`로 취급하지 않는다.
2. 기존 설정집 캐릭터(대표 8종과 D-47의 똑단이)의 정체성 원문은 [대표 설정집](../02_Content/CNT_Character_Main.md)에 유지한다. 캐릭터별 원본 문서는 항목별 링크와 ID·이미지 대응을 제공하는 진입점이다. 기존 서사를 복사해 두 정본을 만들지 않는다. 새 캐릭터는 원본 문서 한 곳에 작성하고 설정집에는 링크만 등록한다.
3. 시각적 문법은 [스타일 가이드](./ART_StyleGuide.md), 실제 전투 파일 규격은 [스프라이트 규격](./ART_BattleSpriteSpec.md)을 따른다. 이 문서는 카드 조판과 전달 절차를 담당한다.
4. 현재 구현은 코드·자산의 근거 커밋으로 확인한다. 기획 방향과 다른 경우 양쪽을 병기하고 차이를 남긴다. 문서의 영어 표기나 새 기획 ID를 기존 세이브 키로 사용하지 않는다.
5. 설정·아트 채택은 기존 [협업 규칙](../../CONTRIBUTING.md) R3·R4·R7에 따라 DD 검수와 사람 확인을 거친다. 이번 문서 추가 자체가 게임 설정·아트 채택 결정은 아니다.

## 2. 디자인 · 서사 · 분류 규칙

- 잊힌 사물의 **구조·재질·작동 방식이 몸과 움직임**이 되어야 한다. 인간에게 양말·우산·촛불 장식만 붙이지 않는다. 귀엽고 살짝 기묘한 말랑한 동화풍, 깨끗한 외곽선, 부드러운 셀 채색, 작은 화면의 실루엣 가독성을 유지한다.
- 카드 바탕은 아이보리·남보라·절제된 금색으로 통일하되 캐릭터 고유색은 원본을 따른다. 모든 캐릭터에게 같은 보라색 옷을 입히지 않는다. 2.3~2.8등신은 기본 가이드이며 원물 구조에 맞게 변형한다.
- 부위별로 `원재료 → 가공/재활용 → 새 구조 → 움직임/쓰임`을 적는다. **보존 요소 3개 · 변경 구조 3개 · 핵심 디테일 3~5개**를 구분한다. 단순 장식도 선택형 외형일 수 있으나, 이번 재활용 기획에서는 구조·실루엣·쓰임의 변화가 드러나야 한다.
- 이야기에는 `이전 감정/결핍 → 확인된 계기 → 형태 변화 이유 → 이후 태도`를 연결한다. 근거 없는 사건·관계·대사는 `[기획 제안]`, 모르는 값은 `미정`으로 둔다. 다른 캐릭터의 서사를 섞지 않는다.

| 외형 유형 | 필수 기록 | 금지되는 추론 |
|---|---|---|
| 진화 단계 | 근거 시스템 문서·결정, 단계명, 선행 조건, 분기, 현재 구현과 기획 방향 | 이미지가 화려하다는 이유로 개화형 지정 |
| 선택형 외형 | 원본 참조, 외형 선택 방식(미정 가능), 독립 외형 ID | 앞 외형 다음에 얻는 순차 단계로 배열 |
| 특별 외형 | 특별한 분류의 근거·적용 범위, 획득/기간의 확인 상태 | 카드에 그려진 이벤트를 실제 운영 정책으로 확정 |

- 실제 유형 자체가 결정되지 않았으면 `미정(검토 중)`으로 남긴다. 선택형·특별 외형의 `선행 진화 단계`는 기본적으로 `해당 없음`, 결정된 의존 조건만 따로 기록한다.
- D-39·D-43의 진화 방향을 참고하되 현재 코드의 `Evolve`와 `Costume`를 문서만으로 재분류하거나 ID를 바꾸지 않는다. 진화 상세는 병합된 [SYS_Evolution](../01_System/SYS_Evolution.md)과 D-45를 따른다. 기억형은 같은 본체+기억 장식 레이어 1겹이며, D-48에 따라 기본 공격 방식 변화도 연결한다. 개화 A/B는 비배타 분기다. 문서 승인과 현재 코드 반영을 구분한다.

### 지킴이 · 잔향이

- 용어와 기본 관계는 [용어집](../00_Overview/KN_Glossary.md)과 [전투 문서](../01_System/SYS_InGameBattle.md) §4.1·§16 #4가 정본이다.
- 지킴이는 본체, 잔향이는 같은 유실자의 작고 단순한 소환 분신으로 식별 요소를 공유한다. [잔향이 규격](./ART_EchoSpec.md) D-48을 따른다. 현재는 **같은 그림을 축소하고 알파 0.75로 표시**하며, 기억형 장식은 생략하고 개화에서 해당 그림을 따른다. 추후 전용 그림은 별도 개발 범위다. 현재 제작에서 별도 반투명 PNG를 중복 제작하지 않는다.
- 첨부 v2의 “동시에 양쪽 편성 금지”는 기획 방향이다. 현재 구현은 같은 **형태**만 배타이고 같은 **계보의 다른 형태**는 양쪽 허용이다. 캐릭터=계보 기준 배타는 전투 문서 §16 #4의 결정 상태를 확인한다. 아트 브리프에서 편성 정책을 새로 확정하지 않는다.
- 외형마다 `본체에서 유지할 것 / 잔향이 크기에서 남길 1~2개 / 생략 가능한 장식`을 기록한다. 스킬은 시각적 표현만 기술하고 능력치·발동 조건·수치는 시스템 정본을 참조한다.

## 3. 컨셉 카드 레이아웃

외형 1종당 세로형 1장, 기본 3:4 또는 제공 레퍼런스 비율. 서로 다른 외형을 작은 격자 한 장에 합치지 않는다. 같은 외형의 확대 컷은 허용한다.

1. **헤더:** `LOST & LOVELY` 배너 → 외형명 → 한 줄 설명(권장 35자 이내) → 소개 2~4줄.
2. **중앙:** 전신이 잘리지 않는 큰 메인 비주얼. 표정·원물·접합 구조가 읽히도록 정면 또는 3/4. 과도한 액션과 큰 배경을 피한다.
3. **측면:** 디테일 2~3개. 재활용 구조·재질 경계·접합부를 우선하고 각각 D1~D3을 붙인다. 실루엣에 따라 좌우 배치를 조정한다.
4. **하단:** 외형 변경 이유·이야기 2~4문장 + 핵심 포인트 2~4개, 필요하면 상황 삽화 1개.
5. **정보:** 획득 방법·등급·이벤트·스킬명은 **확인된 것만** 넣는다. 미확정이면 생략하거나 `미정`. 팔레트는 필요 시 4~6색. 대표 대사는 원문 또는 `[기획 제안]`임이 분명한 문구만 사용한다.
6. **출처와 상태:** 외형 문서 ID, 문서 리비전(커밋), 기획 상태, 이미지 역할을 카드에 작게 표기하거나 외형 기획서의 이미지 대응 행으로 연결한다. 분위기가 공식 설정집처럼 보여도 승인되지 않은 카드는 `컨셉 제안 · 검토 중`이다.

카드용 종이 질감·프레임·금빛 장식이 캐릭터 몸 전체에 침투하지 않게 한다. 따뜻한 동화 감성을 유지하고 실사·3D·공포·고어·과밀 장식을 피한다.

## 4. 이미지와 별도 텍스트 대응

외형 기획서 한 파일이 **텍스트·아트 지시의 정본**이다. 별도 `BRIEF_v01.md`, `ART_NOTES_v01.md` 사본을 만들지 않고 같은 문서의 제작·피드백 절을 갱신한다. 버전은 Git 커밋으로 기록한다.

| 대응 키 | 이미지 | 외형 기획서 |
|---|---|---|
| 정체 | 이름·원물·눈·핵심 구조 | 원본 링크, 보존 요소 |
| 변화 | 전신과 구조 확대 | 부위별 전→후 표 |
| D1~D3 | 확대된 실제 부위 | 같은 번호의 위치·재료·색·움직임·금지사항 |
| 색·재질 | 견본·하이라이트 | 주조/보조/포인트의 용도, 확정값 또는 제안값, 불투명도·광택·질감 |
| 서사·획득 | 카드 문구 | 검수된 원문, 근거, 기획 상태 |
| 파일 대응 | 공유 페이지의 이미지 이름 | 이미지 URL/실제 경로, 역할, 참조한 문서 커밋, 검수 결과 |

- 이미지 AI가 한글을 틀리면 **검수된 Markdown 원문이 정본**이다. 텍스트 없는 일러스트·카드 바탕과 편집 가능한 한글 레이어를 분리 조판할 수 있다. `텍스트 없는 포스터 금지`는 최종 카드의 설명 누락을 막는 뜻이며 중간 조판 레이어를 금지하지 않는다.
- 두 산출물의 구조·이야기가 다르면 원문과 근거를 확인한 뒤 수정한다. 맞는 그림에 맞춰 미확정 설정을 확정하지 않는다. 담당자가 이견을 결정할 때까지 `불일치 · 검토 중`으로 둔다.
- 재질 설명은 “예쁘게” 대신 `천 솔기 방향·촛농의 흐르는 경계·우산살과 천의 접합`처럼 그릴 수 있는 문장으로 쓴다. 색의 HEX를 임의로 확정하지 않는다. 카드 견본 4~6색과 캐릭터 본체의 메인/서브/포인트/중립 구성은 별개다.

## 5. 저장 위치 · ID · 연결

- 원본: `Docs/02_Content/CNT_Character_<Name>.md`. 외형: 같은 폴더 `CNT_CharacterAppearance_<Name>_<Appearance>.md`. 기존 이름 규칙(접두어·PascalCase·공백/버전 접미사 없음)을 따른다.
- 기존 캐릭터 원문은 설정집에 보존하며 각 캐릭터 문서에서 해당 절로 링크한다. 외형 문서는 캐릭터별 원본 문서로만 연결하고 성격·탄생 배경을 재서술하지 않는다. 설정집과 원본 문서에는 외형 링크를 역으로 등록한다.
- **문서 관리 ID ≠ 런타임 ID.** 문서 ID는 파일 stem을 사용한다. `lineage_id`·`form_id`·`costume_id`는 코드에 실재하는 값만 기록하며 없는 값은 `미정(미등록)`으로 둔다. 표시 이름 변경으로 키를 바꾸지 않는다.
- 현재 실제 이미지 폴더는 PR #2의 `Assets/_Project/Art/Characters/`(형태), `Costumes/`(선택 외형), `Concept/`(기존 컨셉)이다. 캐릭터별 하위 폴더는 없으므로 새로 만들지 않는다. 같은 ID가 Characters와 Costumes에서 다른 용도로 쓰일 수 있어 **종류·경로까지 함께 기록**한다.
- 기존 파일은 이동·이름 변경·덮어쓰지 않는다. 분석 시 `develop`에는 본체가 없으므로 PR #2의 근거 커밋으로 연결한다. 본체 병합 후 실제 파일을 확인하고 문서 상대경로로 바꾼다. 존재하지 않는 파일에 링크하지 않는다.
- D-24: **새 시안·중간본은 Notion 아트 페이지/팀 보드**에 두고 문서에는 URL·이미지 이름·상태·문서 커밋을 기록한다. 이번 채팅의 카드가 외부에 등록되지 않았다면 `공유 URL 미등록`이라고 적는다. 기존 Git 컨셉 파일은 그대로 보존한다. 승인된 최종본만 기존 에셋 폴더에 `.meta`와 함께 등록한다.

|---|---|---|
| 1 원본 확인 | 정체성·원물·성격·고정 요소·현재 이미지와 출처 확인 | 원본 문서 링크·기준 커밋·미정 목록 |
| 2 외형 기획 | 유형과 재활용 전→후, 감정 변화, 보존/변경 요소 작성 | 외형 문서·문서 ID·기획 상태 |
| 3 이미지 | §3 카드 또는 명시한 기본형 시트 모드로 생성. 필요 시 실루엣 러프 2~3안부터 검수 | 원본/외형 참조 역할·이미지 URL·생성 도구/사용 프롬프트·참조 커밋 |
| 4 상세 텍스트 | 동일 외형 문서의 재질·색·구조·D1~D3·문구를 검수 | 이미지↔텍스트 대응표·불일치 목록 |
| 5 아트 전달 | 원본·외형·이미지·제작 컷·금지 요소·기술 규격 함께 전달 | 담당·작업 범위·필요 컷·완료 조건·미정 항목 |
| 6 결과 검수 | 정체성·재활용 의도·작은 크기·텍스트·규격 확인, DD 검수·사람 확인 | 결과·반려 사유·채택 링크·최종 에셋 경로 |

기획 상태 `검토 중 / 확정 / 폐기`와 문서 상태 `Draft / Review / Approved / Deprecated`는 별도다. 기획 확정에는 DD 결정 링크가 필요하고, 폐기는 기록 보존·사용 중단을 뜻한다. 기술 검수 통과나 PR 생성만으로 `확정`을 부여하지 않는다.

### 전달 묶음 (외형 기획서의 제작 지시 절에 작성)

- 원본 문서 / 외형 문서 ID / 각각 기준 커밋 / 기획 상태 / 최신 변경점
- 원본·외형·재질·레이아웃 레퍼런스별 실제 URL 또는 경로 및 **어느 부분을 참고하는지**
- 컨셉 카드 + 검수된 본문 + D1~D3 + 유지/변경/금지 사항
- 필요한 컷: 전신·정면·3/4·후면·구조 확대·표정·동작 중 필요한 것만, 장수·규격·용도 명시
- 지킴이/잔향이 적용, 리소스 후보 경로·런타임 키(미정 가능), 검수자·피드백·완료 조건

## 7. 실제 게임 리소스 단계

정확한 수치·예외는 [ART_BattleSpriteSpec §2](./ART_BattleSpriteSpec.md#2-기획-방향-to-be--규격--dd)가 정본이다. 캐릭터 공통: **1024×1024, 내용 높이 922, 바닥 y=963(위에서), 중심 x=512, 좌우 여백 ≥40, 투명 배경**, PPU 100·중앙 pivot. 64px 축소와 잔향이 크기·알파에서 확인한다. 허용 오차와밝기는 규격 문서대로 검사한다.

- 카드 글자·양피지·테두리·획득 배지·바닥 그림자·UI를 캐릭터 PNG에 구워 넣지 않는다. 채택된 본체·장식·필요 레이어를 분리하고 애니메이션 가능성은 실제 구현 범위와 대조한다.
- M1은 **현재 아트·1장+코드 트윈**(D-35·D-41)이다. 시안 작성만으로 게임 교체·추가 포즈·프레임 애니메이션을 확정하지 않는다.
- Unity에서 임포트와 `.meta`/GUID를 확인한다. 기존 참조를 깨는 임의 이동·이름 변경은 하지 않는다. Unity 미실행이면 기술 항목을 `미검증`으로 남긴다.

## 9. 검수 체크

- [ ] 원본 정체성·원물 구조·고정 특징과 외형 의도가 일치한다.
- [ ] 진화/선택/특별의 유형과 근거가 분리되어 있고 임의의 선후 관계가 없다.
- [ ] 재료·접합·동작을 실제 그릴 수 있고 실루엣만으로 차이가 읽힌다.
- [ ] D1~D3, 팔레트, 이야기, 획득 정보가 이미지·본문에서 같은 의미다.
- [ ] 제목·설명·대사의 한글을 본문과 대조했으며 오류를 수정했다.
- [ ] 미정·제안·현재 구현·기획 방향이 구분되고 다른 캐릭터 서사가 섞이지 않았다.
- [ ] 외형 문서는 원본으로, 원본은 외형 목록으로 연결된다. 이미지 URL은 열리고 역할·문서 커밋이 기록되어 있다.
- [ ] 런타임 ID·파일 이동·데이터 변경 없이 새/기존 자산을 구분했다.
- [ ] 실제 납품은 기술 규격·알파·기준선·축소 가독성·Unity 임포트를 별도로 검수했다. 실행하지 않은 항목은 미검증이다.
- [ ] 채택 결정·DD 검수·사람 확인과 반려/수정 사유가 남아 있다.

## 10. “아트 보고” 요청 시 보고 형식

사용자가 “아트 보고”라고 요청하면 최신 develop·관련 PR·실제 전달 산출물을 다시 확인하고 다음 순서로 보고한다. 자동 예약이나 외부 메시지 발송을 뜻하지 않는다.

1. 기준일·확인한 Git 범위·이전 보고 이후 바뀐 내용.
2. 전체 현황: 캐릭터 수·기존 이미지 유무·현재 집중 대상. 이미지 장수와 캐릭터 수를 구분.
3. 캐릭터별 상태 표: 기획 / 시안 / 기술 검수 / 최종 채택 / 게임 적용과 남은 작업·우선순위.
4. UI·전투·공통 가이드의 필요한 작업, 재사용 우선. 목록의 건수와 파일 수를 구분.
5. 미정·막힌 항목·Unity 미실행·PR 충돌 등 확인이 필요한 사항.
6. 다음 작업 순서와 실제 산출물·근거 문서 링크.

시안 생성·계측 통과·기획 확정·아트 채택·게임 적용은 각각 다른 상태다. 근거 없는 진척률·소요시간·완료 수를 만들지 않는다. 문서 요약과 실제 목록 수량이 다르면 불일치를 밝히고 실제 항목으로 집계한다.
