## 1. 범위와 상태

사용자 지시 순서인 **홈·전투 통합 배치 → 링·예고 마커·HUD → 성향 아이콘·수선등·창문 → 편성·실패 화면 검수**에 따라 검토 묶음을 제작했다.

- 화면: 홈·전투, 편성, 실패 원인 2종, 강화 시트 위 전투 알림 4종. 강화 시트는 알림과 CTA 목적지의 배치 검토용이며 성장 시스템 전체 구현이 아니다.
- 신규 후보: **47종의 SVG 원본과 같은 크기의 투명 PNG**, 수선점 소등 기본 PNG 1장, 홈·전투 톤 참고 이미지 1장.
- 재사용: 기존 밤거리·캐릭터 5종·받침·덱 프레임 참조·탭·패널·등불·잔향·바구니를 조사했다. 실제 검토 화면에 사용하는 파일과 원본 커밋·해시는 묶음의 `reference/manifest.json`에서 추적한다.
- 새 후보는 **채팅 전달물**로 보존한다. D-24에 따라 Git/LFS에 시안 이미지를 추가하지 않는다. 저장소에는 본 기록과 기존 문서의 확정 결정 불일치 정리만 반영한다.
- **최종 채택, Unity 임포트, 실기기 적용은 미완료**다. 게임 코드·씬·프리팹·데이터·기존 에셋을 교체하지 않았고, `decisions.md`에 채택 결정을 추가하지 않는다.

## 2. 화면 배치 검토

### 2.1 홈·전투

- 상단 메타 바와 전투 HUD를 분리하고 스테이지·타이머·Wave·보스/남은 적 상태를 표시한다.
- 전장 전체, 작은 중앙 수선점, 지킴이 5명, 8방위·빈 방향, 위험 방위, 지속 압박을 함께 보인다. 지킴이 체력바는 넣지 않는다.
- 잔향 줄 오른쪽에 수선등, 그 아래 덱 6칸 1열, 하단 탭 **강화·편성·유실자·사냥·원정·소환·상점** 7칸을 배치한다(D-44).
- 기존 문서의 11% 전장 시작선보다 이 후보의 상단 정보 영역이 넓다. 기준 화면은 상단 약 13%, 전장 하단 64%, 잔향/퀘스트~71%, 덱~80%, 하단 탭~100%다. **검토용 미세 조정이며 승인된 비율의 새 정본이 아니다.** 최종 배치는 Unity 안전 영역·최소 글자 크기 검수와 함께 조정한다.
- 알림은 시트 위에 별도 칩으로 표시하며 누르면 홈으로 복귀한다. 보스·위기·클리어·실패 4상태를 비교한다.
- 일반·예고·보스·최후의 쇄도·내구 위기·잔향 부족·소환 상한·튜토리얼 잠금을 검토한다.
- 브라우저의 탭·소환·강화 반응은 **상태 비교용 단순화 모델**이다. 전투 판정·시간·AUTO·배속·자원 수급의 실제 시스템 구현이 아니다. 옆 탭 전체 기능을 새로 구현한 것으로 표시하지 않는다.

### 2.2 편성·실패

- 편성: 8슬롯·지킴이 5명·빈 방위 빗금·위험 우선 배치·파견 중 배지를 비교한다. 슬롯 이동/맞바꿈 후 빈 방향 표시가 함께 갱신된다. 클릭 선택 후 방향 선택과 마우스 드래그를 제공하며, 모바일 드래그 감각은 Unity 검수 대상이다.
- 방위는 색에 더해 글자와 점 개수를 병행한다. 경고는 삼각형·빗금, 지속 압박은 줄무늬로 구분한다.
- 실패: 방어 문제/화력 부족의 원인·권장 행동과 **재도전·편성 변경·강해지기** 3개 CTA를 비교한다. 원인 변경은 검토 도구 바깥 조작으로 하고 실제 리포트에 원인 선택 버튼을 넣지 않는다.
- 화면 외부에 검토용·수치 예시·기준 결정·실제 게임 아님을 표기한다. 내부의 장식 문구·설명은 카피 제안이며 설정·스킬·획득 조건을 추가하지 않는다.

### 3.1 수선점 단계 점등

기존 `Battle/shop.png`에는 창문 불빛이 이미 그려져 있다. 밝기 오버레이만으로 소등 상태를 복구할 수 없어, 이미지 생성 도구로 **소등 기본 후보**를 별도 제작했다. 기존 PNG는 보존했다.

- 소등 후보: `concepts/shop_dark_base.png`, **1254×1254 RGBA**, 투명 배경. 원본 768²와 픽셀 단위로 동일한 편집본은 아니므로 기존 스프라이트의 교체 승인으로 보지 않는다.
- 점등 레이어: `candidates/shop_light_1~5.png`, **768×768 RGBA**. 소등 후보와 같은 사각 Rect에 정규화해서 표시한다. **텍스처의 픽셀 크기가 동일하다는 주장은 하지 않는다.** 최종 납품 전 기본 후보와 레이어를 768²의 같은 기준으로 출력하고 창문 프레임을 재검수해야 한다.
- 단계 순서 제안: 정문 창 → 왼쪽 아래 → 오른쪽 아래 → 왼쪽 위 → 중앙 큰 창. 작은 오른쪽 중간 창은 비점등으로 남긴다.
- `build-assets.cjs`의 `windows` 좌표는 768 논리 좌표다. 타원형 유리 면·십자 프레임 제외 마스크와 주변 빛 번짐을 레이어로 분리했다. 곡면·사선 프레임에 대한 최종 작화 정합은 별도 검수 대상이다.

### 3.2 Unity 전달 설정 제안

아래는 **미적용 제안**이며 `.meta`의 임의 GUID를 만들지 않았다.

| 항목 | 제안 |
|---|---|
| 일반 UI 아이콘 | Sprite (2D and UI), Single, sRGB On, Alpha Is Transparency On, Mip Maps Off |
| 메시·샘플링 | Full Rect, Bilinear. 실제 표시 크기·압축 후 32px 가독성 재검수 |
| 버튼 9-slice | `lantern_button_*`: L/B/R/T 각각 24px. 최종 적용 전 모서리 늘어짐 확인 |
| 알림 칩 | `alert_*`: 20px border. 좌측 아이콘은 늘어나는 중앙 밖에 두고, 글자는 별도 TMP |
| 링/방위 | Pivot (0.5, 0.5), 0°=N, clockwise 45°씩. Unity Z 회전 부호는 UI 좌표계에서 확인 |
| 크기 | 논리 크기와 Texture pixels를 구분. PPU/Canvas Scaler는 기존 빌더 기준 유지 |
| 적용 | 채택 후 최종본만 LFS에 추가, Unity가 만든 `.meta`를 함께 커밋. 연결은 I-10 개발 작업에서 수행 |

## 4. 전달 묶음과 검증

채팅 산출물 `Project_KN_UI_Review_01.zip`:

- `index.html`, `review.css`, `review.js`, `manifest.js`: 로컬 검토 화면. 외부 CDN·폰트·API 호출 없음.
- `candidates/`: 47종 SVG/PNG. `asset-manifest.json`: ID·상태·크기·9-slice·추가 주의사항.
- `reference/`: 기존 리소스 34개와 원본 커밋·해시 목록. 재사용 적합성 확정과 파일 존재 확인을 구분한다.
- `concepts/`: 소등 기본 후보와 이미지 생성 톤 참고. **톤 참고 화면의 캐릭터·수치·카피는 정본이 아니다.** 실제 배치 검수 화면은 저장소 캐릭터 5종을 사용한다.
- 화면 캡처, 5단계 점등 비교, `verification.json`, `SHA256SUMS.txt`, README. 다운로드 묶음 자체가 리뷰 산출물이며 팀 내부 공유용이다.

검증 범위는 PNG 크기·알파·내용 존재, 32px/64px 시트 육안 비교, 9:19.5/9:16 화면 안 고정 조작부, 360/390/768px 검토 페이지 가로 넘침, 상태 전환 및 원인별 CTA다. 구체 실행 결과는 `verification.json`에 남긴다.

아트 채택·Unity 임포트·압축·TMP 폰트·실제 전투·잔향이 트윈·실기기 터치·성능은 이 검증의 범위가 아니다. 관리형 Chromium의 직접 `file://` 열기는 정책에 의해 차단되어 HTTP 로컬 서버로 확인했다. 이 제한을 우회하지 않았으며 README에 HTTP 실행 방법을 적는다.
