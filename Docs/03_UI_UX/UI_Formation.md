## 2. UI 요소별 기능 · 인터랙션

1. **뒤로** : 미저장 변경이 있으면 저장/취소 확인 (UI §4.2). 편성은 바로 저장되는 구조라 M1은 확인 없음 (현재 구현)
2. **팀 전투력** : 현재 `PowerSystem.TeamPower` (D-29 #7). 배치 바꿀 때마다 숫자 롤링
3. **권장 전투력 · 평가** : 현재 스테이지 기준 여유 / 도전 / 어려움 (현재 구현)
4. **위험 방위 · 지속 압박 표시** : `Stage_Battle_Config.danger_sectors` · `constant_pressure_sector` (D-34). 링 위 해당 방위에 ▲ · 줄무늬 마커와 같은 위치
5. **8방위 링** (§6.1)
   - 슬롯 8개(N · NE · E · SE · S · SW · W · NW), **지킴이 최대 5명** — 3칸은 반드시 빔
   - 캐릭터 카드를 링 근처로 드래그 → 가장 가까운 방위에 **스냅**
   - 슬롯 ↔ 슬롯 드래그 → 이동(빈칸) · 맞바꿈(찬 칸)
   - 슬롯 길게 누름 → 빼기 (목록으로 복귀)
   - 6번째 지킴이를 놓으려 하면 → 마지막 드롭 취소 + 링 흔들림 (UI FM-001)
6. **요격 부채꼴 프리뷰**
   - 배치된 지킴이마다 담당 부채꼴(성향 `CombatStyle`별 폭 · 사거리) 반투명 표시
   - **덮이지 않는 방위는 빗금** → 위험 방위(④)와 겹치면 빨간 빗금 = "여기가 비었어요"
   - 배치를 바꾸면 즉시 갱신 (1프레임 이내, UI §17.3)
7. **잔향이 덱** (6칸, 6번째는 2-9 클리어 전 🔒)
   - 카드를 덱 칸에 놓으면 잔향이로 등록. 카드에 비용 · **성향 아이콘**(§18.1)
   - 칸 순서 = AUTO 순환 순서 (현재 구현)
8. **시너지 요약** : 활성 시너지 수 + "1명 부족" 힌트 → 탭 → 시너지 상세 (현재 구현)
9. **자동 편성 · 프리셋**
   - [자동 편성] : 현재 구현 규칙 + **위험 방위 우선 배치** 🆕 (위험 방위 → 지속 압박 → 나머지 순)
   - [프리셋 1 · 2 · 3] 🆕 : 탭 = 불러오기, 길게 = 현재 편성 저장. M1은 3칸 [가정]
   - 스테이지별 마지막 편성 기억 (시스템 §6.1) — P1
10. **필터 · 정렬** : 역할 · 성향 · 원물 / 전투력 · 레벨 · 획득순
11. **보유 캐릭터 목록**
   - 카드: 얼굴 · 레벨 · 성향 아이콘 · 상태 배지
   - 상태 배지: `지킴이 N` · `덱` · **`파견 중`(회색 + 남은 시간, 배치 불가)** (D-27 #5)
   - 이미 반대쪽에 있는 형태를 고르면 → "지금은 직접 나가 있어요" / "잔향을 준비 중이에요" 안내 후 이동 여부 확인 (UI FM-001)

## 4. 상태 · 예외
| 케이스 | 처리 |
|---|---|
| 지킴이 0명 | 저장 가능, 전투 진입 시 "지킴이가 없어요" 약한 경고 — 진입은 허용 (최소 1인은 권장, 시스템 §6.1) |
| 빈 위험 방위 있음 | 빨간 빗금 + 상단 ④ 깜빡임 1회. 진입 차단 없음 |
| 파견 중 캐릭터 | 목록에서 회색, 드래그 불가, 탭 → "○분 뒤 돌아와요" |
| 원정 출발 시 편성된 캐릭터 | 원정 화면에서 "편성에서 빠져요" 확인 → 확인 시 편성에서 제거 🆕 (D-27 #5의 반대 방향) |
| 덱 6번째 칸 잠김 | 🔒 + "2-9를 클리어하면 열려요" |
| 같은 계보 다른 형태를 같은 쪽에 | 현재 규칙: 불가 (`LineageLimit`) → "한쪽엔 한 형태만" 토스트 (§16 #4 결정 후 재검토) |

## 6. ① 현재 구현 — 브라우저 개발 참조 (Unity 별도)

`Tools/UIReview` 0.8.5에서 첫 기본 포인터 하나가 슬롯/프리셋의 길게 누르기·드래그를 제어하도록 보완했다. 다른 손가락은 타이머를 새로 만들거나 기존 입력을 이동/해제/취소하지 않는다. 콜백은 동일한 제스처와 연결된 버튼을 확인한다. 기존 0.6초 슬롯 해제·프리셋 저장·맞바꿈·탭 불러오기는 유지한다.

실제 Chromium 복수 터치 검사 6항목과 기존 회귀 검사를 포함한 12개 묶음·92개 항목을 확인했다. [검사 기록](../../Tools/UIReview/formation-pointer-verification.json) · [개발 전달](../../Tools/UIReview/README.md). 이는 브라우저 참조의 구현 상태이며 게임의 편성 저장/재시작·Unity 입력 시스템을 바꾼 것이 아니다. **Unity 미실행 — 미검증**, 실기기 확인은 별도다.
